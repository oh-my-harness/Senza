# 序言：如何使用本教材

## 这套教材试图解决什么问题

很多 Agent 教程从一个聊天接口开始，再逐步增加函数调用、记忆、工作流和多 Agent。这样的
学习顺序容易让人得到一个错觉：Agent 只是“模型外面再包几层功能”。在真实工程中，更重要的
问题是：谁维护循环，谁允许动作发生，谁保存外部状态，谁验证结果，以及能力之间如何组合而不
破坏已有行为。

本教材因此不从某个“大而全 Agent”出发，而从一条可以逐步验证的 Developer Agent 主线出发：

```text
理解任务 → 选择工具 → 观察环境 → 修改状态 → 执行验证 → 提交答案
```

随着章节推进，我们会把上下文治理、安全策略、工作流、知识、协作和评测逐层装到这条主线上。
每增加一种能力，都要回答三个问题：它属于哪一层？它在哪个明确边界生效？我们有什么证据证明
它真的生效？

## 四层架构地图

```text
Developer Agent / Workflow 应用
              │  定义任务与业务完成条件
      Senza Python 装配面
              │  选择并配置能力
 Runtime Agent Core + 12 Hooks + Plugin 协议
              │  执行循环、约束与组合协议
 Model / Tool / Store / Knowledge / OS / MCP 等外部后端
                 保存或改变真实环境状态
```

这四层不是按“重要性”划分，而是按变化速度和职责划分。Core 要尽量稳定；Hook 位置固定但实现可
替换；Plugin 在构建期组合能力；具体应用和外部后端可以根据场景快速变化。Senza 的价值是把底层
Rust Runtime 的这些能力整理成 Python 可装配面，而不是再实现一套并行的 Agent Core。

## 教材、实验与 live example 的分工

- **教材正文**解释设计动机、架构关系、源码入口和能力边界；
- **Academy recorded 实验**提供无密钥、可重复的教学轨迹和确定性断言；
- **live example**调用当前 Senza API 与真实 Provider，用于证明实际装配链路；
- **Runtime/Senza 测试**是关键行为和回归边界的最终工程证据。

recorded 模式不会伪装成真实在线运行。它适合回答“事件之间有什么因果关系”，不适合证明模型
一定会做出某个选择、回调一定已被 Runtime 调用或状态已经持久化。

## 建议的学习方法

第一次阅读时，按 01 到 10 的顺序完成每章的“执行故事”和 recorded 实验。第二次阅读时，沿着
源码链接核对对应接口，再选择有条件运行的 live example。若你准备基于 Senza 开发应用，至少应
完成前六章；若你维护框架或设计平台能力，还应完成第七到第十章，并重点阅读每章的能力边界。

每章结束后，不要只检查“示例有没有跑通”。试着用自己的话回答：

1. 这个能力为什么不直接写进 Core？
2. 它在哪个 Hook、Tool 或外部接口边界生效？
3. 如果删除它，哪条 trace 或哪项测试会最先失败？
4. 它依赖什么外部后端或上下文数据？

## 环境准备

仅运行 recorded 实验时，需要 Python 标准库和 `pytest`。在 Senza 仓库根目录执行：

```powershell
python academy/labs/01_react_tool_calling/demo.py
python -m pytest academy/tests academy/labs -q
```

live 模式会委托 `live-tests/examples/` 中的权威示例，通常还需要构建 Senza、配置 Provider 和
对应密钥。每个实验 README 会列出自己的真实入口；缺少外部条件时应明确跳过，而不是用 recorded
输出冒充 live 结果。

## 成熟度标记

正文使用三类成熟度：`stable` 表示当前 API、源码与测试共同支持；`teaching` 表示 Academy 为
讲解方法新增的教学实现；`preview` 表示契约或部分装配已经存在，但 Python 端到端产品链路尚未
完整。成熟度不是对理念价值的评价，而是对当前证据强度的声明。
